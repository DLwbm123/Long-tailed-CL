# ACTION-TRACE1：固定动作的即时收益、训练执行与任务末读出

2026-10-09 执行前冻结。用户在收到“先判断动作价值、反馈识别能力、再判断RL必要性”的分析后明确授权执行。代码与CPU检查在GPU预检前冻结；本协议不复活已停止的完整RL矩阵。

## 1. 唯一问题与最小范围

现有竞争动作是否包含能改善一个局部任务末分类结果的候选？原即时代理奖励能否识别它？若选择时有收益，收益在编码器更新、训练头更新或任务末重新拟合的哪一环改变？

只取ISIC/HK的第二任务：这是首次同时包含新旧类的任务，按任务位置选择，不按哪个状态表现最好来选。所有fork从各自原static_pc轨迹的stage_1出发，一次动作执行一个epoch，与原动作持续时间一致；随后诊断性提前执行任务末refit。原完整任务是两个epoch，因此本轮不是原轨迹的精确续跑、完整CL结果或独立确认。

## 2. 候选、配对与固定预算

- 沿用既有8维edge描述：old→new、new→old、同组，原型相对难度、标准化负margin、类均值余弦相似度、目标/源计数对数比、margin离散程度。
- 17个唯一候选：零系数与每维系数的+1/-1单位向量。其余维为0。沿用原log(2)×tanh、至少半数基准边质量与总竞争质量守恒，不加beta=0或新动作。
- 本轮强制执行全部预先冻结候选，包括原reward非正者，以诊断执行门的假阴性。这是隔离的反事实fork，原正式算法执行门保持>1e-8；不会改写历史模型或把负奖励动作部署到正式轨迹。
- GPU0 ISIC候选0..8，GPU2 ISIC候选0及9..16，GPU1 HK候选0..16。ISIC重复一次零候选作为跨GPU配对检查，不增加种子或唯一候选。
- 34个唯一fork、35个实际fork。ISIC每fork2292 fit/587 meta、36步；HK93 fit/24 meta、2步。总更新18×36+17×2=682，策略更新0。两项GPU预检均仅第一次反传、0适配器更新。
- 每fork重新加载相同初始适配器，重置Python/NumPy/Torch种子74002，重新建立AdamW及同一DataLoader生成器；增强按既有样本索引/epoch固定。必须验证各fork批次索引序列一致。split_seed74002、batch64、lr.0003、weight_decay.01、FD10、prototype1、competition beta.5、ridge.001、proximal.01、梯度裁剪5均沿用。只执行第一个epoch，不执行第二epoch调度。
- 当前meta始终不更新编码器，也不进入初始/fit-only bank及运输。前序旧bank仍含其历史meta，这是原方法状态，不能声称旧类统计为独立验证。

## 3. 五个读出点

1. `immediate`：动作头在初始编码器上的读出；原即时奖励由旧矩风险+当前留出meta风险计算，并保留原分组负收益惩罚和allocation KL。
2. `encoder_only`：训练后的编码器，仍用最初动作头。用于观察固定头下的表征变化。
3. `trained`：训练后的编码器与最后一个小批次解析头。该头按原实现是在最后一次适配器更新之前求得，不伪装成更新后的全量最优头。
4. `fit_refit`：训练后仅用当前fit重新构建新矩和旧类运输偏移，并按同一系数重新生成边权、求头。
5. `all_refit`：按原任务末机制加入当前meta，重新计算运输、统计、边描述与头。此时meta表现是参与拟合后的诊断，不能作独立反馈。

训练前/后私有特征、适配器、各头与边矩阵保留，支持事后复核；不会用缺失状态推断因果。训练过程中不读取开发影像。三个worker的35个训练fork全部完成后才打开开发读出屏障；任一训练worker或suite失败则不开屏障。各候选统一报告fit/meta与开发旧类、新类、全部已见类的BA、平方风险、分数、margin、逐类正确数及相邻读出点paired变化。

## 4. 冻结分析规则

- 主要可用选择器仅采用初始原代理reward：最高reward严格>1e-8时选最高者，否则零动作；并列按较小候选索引。开发结果不能改变候选、强度、轮数或后续执行。
- 事后oracle只作为特权诊断：在本轮有限候选中找最终all_refit开发BA最高者。它不是可部署选择器，不作为新的方法结果或独立确认。
- 每个读出点均先减去同一配对零动作的结果，再比较这些“动作相对收益”如何跨阶段改变；不能把正常训练本身带来的变化归给动作。
- 分别报告代理排序与最终BA的秩关系、正reward的有益/有害计数、非正reward漏掉的候选、可用选择器与有限集oracle的差距；重复或恒定分数明确处理，不虚构相关性。
- 同时报告旧类与新类增损。标记“最终全部BA严格提高且旧/新BA均不下降”的有限集候选；所有数值仍完整披露，不只挑Pareto候选。小分母改善必须给正确数和paired变化。
- 若有限候选未提供最终收益，只能说该候选集合未找到，不证明整个连续动作空间无解；若oracle有益但代理漏掉，才支持反馈辨别不足；若即时相对收益在后续切点消失，支持定位执行/重新拟合问题。只有反馈可靠而优化器未实现时才讨论优化器瓶颈，本轮没有新RL优化器比较，不能声称该分支已验证。
- ISIC两份零动作须检查起始参考头、训练批次顺序、各读出预测/指标。若跨GPU零动作不一致，保留分片内配对比较，不合并出无条件的全候选oracle结论，不自动重复训练。
