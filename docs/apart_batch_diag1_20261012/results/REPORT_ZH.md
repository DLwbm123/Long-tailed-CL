## 诊断结论：评价差异未改变预测，w近零得到验证

两数据集三模式的全部stage预测逐样本一致，全部最终/平均指标、31类召回的增量均为0pp，救回0/损伤0。原mixed与旧报告每stage每类recall精确一致。ISIC T1逐样本相对多数票有8次任一池选择改变，但预测不变；其余stage观察到的模式间路由改变为0。这否定“本批checkpoint低分由所测评价批次差异造成”的解释；不代表训练时batchwise路由没有影响，也不能证明对任意未来模型都不存在批次依赖。

最终w条件诊断：ISIC295/295均≤.01（mean1.2860182e−10）；HK1697/1698≤.01和≤.05（mean5.7934519e−5，median1.6196666e−20）。全部31类最终都通过预注册近零screen。HK T5并非所有组都近零：native rare组mean.19414063、51/70≤.05，screen FAIL；新类21的首次mean.5568032，到T6变为5.9534681e−10（n=4）。这个短暂恢复的例外完整保留，不能称全程恒零。

当前checkpoint上的近零w是直接观察，训练epoch内何时坍缩及其因果性能影响仍未验证。w为额外辅助CE的权重，不是专家编号，不参与推理；即使w趋0，联合双head CE和pull仍训练两池，不能称辅助池完全不训练。作者后期10w(1−w)^2缺少对w趋0的惩罚与此现象一致，但本轮没有修该公式/重新训练，不能声称修正必然提升。旧类保持、跨任务竞争和作者后续恒定学习率仍是解释方向。

工程谱系：客户端CPU部署换行语法在SSH前被拒绝，0远端写/0GPU；报告客户端为读取模式常量误导入torch，因本机报告解释器缺torch在SSH/收集前失败，去除不必要GPU依赖后成功。两项都不是GPU诊断失败或重跑。两个GPUworker各只执行一次，原模型/训练和test均不动。报告w格式使用科学计数，避免小值被固定小数误显示成精确0。
