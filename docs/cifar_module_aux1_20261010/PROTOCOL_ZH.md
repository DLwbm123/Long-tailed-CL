# CIFAR 辅助配对验证：冻结协议

用户明确授权补一轮CIFAR，同配置原基线与目前最有希望的候选比较，不影响医学实验；随后明确仅用GPU0/1/2，不使用GPU3。本轮独立于医学研究轮次。只使用GPU2，顺序执行，GPU0/1留给医学研究；不修改既有进程、冻结源码、协议或医学test权限。若GPU2显存不足，停止派发并报告，不自动抢占医学GPU或使用GPU3。

候选在读取本轮CIFAR评价前锁定为第二轮 **local_transport（局部先验＋区域运输）**。相对原static_pc，其医学证据ISIC BA+1.28998pp、tail+3.31246pp、new−0.11364pp，HK BA+0.01330pp、tail0、new0。ISIC通过开发门，HK尚未达到BA+1pp目标。第六轮CE、更强归一化、梯度投影及后续残差/读出未显示更稳健的双数据集收益。选它是验证已有最好且较稳健的局部机制，不是声称已解决HK，也不按CIFAR结果挑候选。

沿用已经准备好的CIFAR-100-LT，IF=100，10847训练图；不重新采样、下载或调整不平衡度。任务50＋5×10类，shuffled顺序沿用已有参考排列。seed/split_seed74002，原身份分组fit/meta约80/20，meta仅在任务末加入训练来源拟合。官方平衡test每类100、共10000图。过去旧方法已用过该test，因此本轮也不是全新独立留出确认。训练前只核对manifest元数据和类计数，不计算test分类分数。

两条正式轨迹：**base为原static_pc主体**，**local_transport仅增加既有局部模块**。两者均从相同预训练ViT与adapter初始化开始重新训练；旧CIFAR cf_linear并非当前竞争头主体，不能用它替代配对base。保留相同全局类/组件充分统计、原型先验、竞争解析头、FD10、AdamW .0003、weight_decay .01、clip5、cosine schedule、两epoch、batch64、workers4、ridge .001、proximal .01与相同训练增强。每臂各任务更新132/24/34/34/38/14，共276；两臂总552。0策略更新，无RL。

局部模块与已结束医学轮完全相同：从原ViT双分支patch token作四固定象限CLS条件softmax池化，减每图四区域均值后归一化。每类保留四个聚合局部均值，各以1/2加入原先验P，原R=(I+PPᵀ)⁻¹及竞争解析拟合保持；预测仍原全局线性头，不添加局部读出分数或可学习头。旧局部均值按当前类均衡每区域before→after均值位移运输，全局mu/Q仍原common_shift。仅保存聚合旧统计，不保存或回放旧影像/旧逐样本特征；真实旧类漂移仍是共同位移近似。固定四区域在32×32图经原224增强后未必提供新增信息，本轮正负都有效。
