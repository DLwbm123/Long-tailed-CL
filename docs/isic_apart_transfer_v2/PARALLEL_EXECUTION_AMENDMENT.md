# Two concurrent trajectories: user-authorized execution amendment

The user requested up to two trajectories on the same RTX 4090 D to improve utilization. One active trajectory occupied about 9.9 GiB; 13.6 GiB remained free. The earlier 83% utilization was an instantaneous sample; later serial samples were already 97–100%. Parallel execution can reduce input/checkpoint gaps but does not imply twice the throughput or continuous utilization above 90%.

All 32 frozen source fingerprints from training commit `6d8bd3e700924c864e229c47efe5f108ce728c78` remain unchanged. `parallel_medical_v2.py` is a separate orchestration entry that imports the same MedicalLearner, session training, checkpoint/restore and evaluator. Training arguments, seeds, preprocessing, sampling streams, losses, batch size 48, 10 epochs/session and the original protocol hash are retained. The actual execution commit and scheduler hash are recorded separately in the private runtime amendment and checkpoint-lock metadata; the original code commit remains the training-source provenance.

The transition waits for an atomic epoch checkpoint, pauses only the owned process group, preserves a hard link to the saved checkpoint and original runtime/lock, validates its epoch and protocol bindings, then resumes from that epoch in an independent worker. Any uncommitted work after that boundary is discarded; committed epochs are retained. This user-requested scheduling transition is distinct from an infrastructure retry.

There are exactly six jobs (1993/1994/1995 × B/C), with at most two live workers. Each exclusively owns its trajectory directory and RNG. Completed session files are restored, never retrained. Epoch logs must contain exactly epochs 1–10 for each session. A coordinator checks paired initialization and S0 equality and all 18 unique checkpoints before launching the unchanged evaluator in a separate process. It preserves the one-test-batch marker and original 24-hour single-GPU wall-time deadline. A failing worker stops the queue; at most one recognized infrastructure retry is shared with the prior scheduler.

`tests/test_parallel_medical_v2.py` passed real subprocess tests for two-worker overlap, maximum concurrency, failure cancellation and missing/mismatched checkpoint barriers. Numerical restore and optimizer/RNG equivalence remain covered by the completed V2 P1 checks. Parallel performance will be reported from a bounded live sample, without changing training settings to chase utilization.
