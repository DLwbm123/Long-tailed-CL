# 固定支持上的类平衡线性CE：标准读出基线

## 依据与唯一问题

上一轮两次固定旧记忆减半中，完整岭的总体宏预测不一致率在ISIC/HK两片开发查询均不高于均值；它不支持“岭普遍更不稳定”的解释。当前比较尚缺直接优化整个线性分类头的类平衡CE基线。此前CE实验优化的是固定ETF下的小适配器、带历史保留项，不能替代本对照。

本轮问题：在完全相同、已经压缩的旧H和未改变的新S上，固定线性函数族与参数化，采用正则CE是否比当前完整岭改善开发BA及旧/新组平衡？这是标准基线，不作为新方法，不证明全历史CE优势或历史压缩损失。

## 冻结拟合

使用原零适配器归一化1536维特征。旧H直接读取原确定性herding产物，不复制输入bank；ISIC旧64+新2290=2354，HK旧169+新95=264。每类总质量1/K，类内均匀。输入DT、有限性、标签范围、计数与零适配器严格验证，复现完整均值头以及完整岭正规方程后才拟合。

仅训练W，不加偏置、不作W列归一化，无保留项。目标为：

`L(W) = (1/K) sum_c mean_{i:y_i=c} CE(8*z_i*W,y_i) + .001/2 * ||W||_F^2`。

初始化直接使用已经封存的完整岭W。固定PyTorch L-BFGS：lr=1，max_iter=200，max_eval=250，history=20，strong_wolfe，tolerance_grad=1e−8，tolerance_change=1e−14；额外硬上限每正式拟合300次closure梯度。拟合终点再计算一次梯度；max_abs<=1e−6才标为收敛。预算终点不收敛时保留全部结果、标为有限优化结果，不自动增步或重试。溢出/非有限值/来源不匹配立即停止。

固定beta与正则系数不是跨损失的最佳超参比较。CE与平方损失尺度不同，同数值正则的有效强度也可能不同，不能把差异排他归因于损失形状。无正则/温度/初始化/核搜索。

## 对照与查询隔离

完整岭为唯一主要对照，均值为次要参考，均不重拟合。CE头先保存并封存，再访问Qfit/Qgate及历史参考聚合。三个头在共享特征上评价全部类的BA/CE、真实类margin/rank、Top2/3、竞争者及逐类救回/伤害/错转错。两个基线计数逐项精确复现，CE容差1e−10。所有查询已用于开发，明确不是独立验证。

既定描述性判定：求解收敛且每个查询总体BA严格提高、旧/新BA各不下降超过1pp，两个查询均满足才记该数据集通过。ISIC/HK都报告；不选择查询、删除小类或根据结果部署新头。

禁止访问原旧S、teacher状态、保留E、原图、新标签及未封存前查询。三个来源DELIVERY绑定保持不变；允许H、新S、原零适配器与两个封存头。访问守卫主动拒绝禁止文件。无未来数据用于拟合。

## 有限预算与工程自检

两个CPU任务各900秒，总墙钟3600秒，2线程，无GPU。两次正式1536维CE拟合，最多600次closure梯度加2次终点梯度；实际迭代、梯度及目标轨迹完整记录。两次工程二维CE拟合，验证对称二类解与二分标量根一致；验证CE梯度解析式和类内复制不改变加权目标/梯度。工程费用与正式费用包含在工作进程驻留，不重复相加。

支持共享特征2618条，查询共享特征2155条，三头logit样本计算6465次；两个新头共32256个float64元素、258048字节，排除未变零适配器。L-BFGS历史与临时特征属工作内存，另报峰值，不混为持续记忆。0原基线拟合、0正式线性求解、0适配器/教师/编码器/记忆更新。保存失败、缺失、超时、全部负结果与费用。
