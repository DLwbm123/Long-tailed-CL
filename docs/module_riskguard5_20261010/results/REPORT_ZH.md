## 为什么这一保护没有解决问题

逐类平方风险是各输出分数误差的总和，argmax正确与否取决于真类和最强竞争类的分数差。很多非竞争输出误差下降可以补偿少数决策边界恶化，因此每个类训练平方风险不升并不推出每个类分类召回不降。ISIC训练统计中的每类风险本来都下降，所以新保护没有触发；这与开发新类少对样本并不矛盾。HK约束确实触发并减少局部分数幅度，但分类结果仍有正负变化。现有证据支持平方风险与分类效用错配，不能排除训练到开发泛化、局部信号不足和共同统计运输误差，不能断言唯一原因。

连续三轮解析读出（raw、conditional、riskguard）均比原static_pc差，继续只换平方风险/输出收缩规则缺乏依据。不进行val幅度扫描，也不人为强制ISIC约束触发。后续若推进，应检验区别于末端读出的机制：用当前训练标签在adapter训练阶段塑造局部判别表征，以停止局部梯度的相同辅助头作为贡献控制，推理仍用既有局部先验和原竞争头；先独立协议、数学/工程检查及源码冻结，不把方案描述当已启动。
