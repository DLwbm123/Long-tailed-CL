# NIH 多标签持续学习代码适配

本分支是独立的工程候选，基于已发布的 A5 源码提交，未修改或发布 A6 的冻结结果。
尚未启动 NIH 正式训练，也没有证据证明多标签版本的奖励、投影或随机采样有效。

## 已实现

- `tools/ml_data.py`：读取数据准备阶段的 14 标签 manifest，保留 No Finding 的全零向量；用布尔掩码区分可见标签与未知/未开放标签。NIH 原始零值是该版本未提取到阳性标签，不等于经医生确认阴性。
- `tools/ml_core.py`：逐标签 sigmoid/BCE；正负权重只从当前任务可见训练标签计算，每个标签存在的正/负组等质量。观测项按数量归一化。FD 使用每张图像可见标签权重的均值；不会把多标签压缩为 argmax。
- 辅助项沿用八次动作、LOO baseline、lagged sigma EMA 和 detached reward 的结构，但动作改为每个可见图像—标签对的二元 Bernoulli。未知位置不参与采样或更新；保持奖励只用于历史已有观测的标签。第一任务不启用辅助项或 FD、不推进动作 RNG、不更新 sigma。
- 随机条件 R05/R01/P01 和确定性 EP01 使用相同二元奖励；P01/EP01 只在参数空间投影辅助梯度，随后一次全局 clip 和一次 AdamW 更新。EP01 仅对应原始随机奖励梯度的期望，不是非线性投影/裁剪后更新的期望，也没有旧类安全保证。
- `tools/ml_statistics.py`：每个标签分别保存阳性/阴性计数、一阶和完整二阶统计量；统计量平移后重拟合固定二元 ridge 头。目标为 -1/+1，包含正则化截距，零分数是判别边界。sigmoid 分数不声称已经校准。这是显式的新适配定义，不是原互斥类别统计量公式的直接复用。
- `tools/run_multilabel.py`：复用原有锁定预训练 ViT、1536 维特征及 adapter pools，训练期间固定 W_start，最后统一使用 W_final；保存阶段边界状态，支持 A、四种奖励配置及 F_S（第一阶段后冻结编码器，后续仅更新统计量/头）。不保存历史原图或逐样本特征用于回放。
- `tools/ml_metrics.py`：逐类 AP、AUROC、F1/召回、micro-F1、有效分母及零召回；没有阳性的标签 AP 记为 null，无双侧样本的 AUROC 记为 null。排名指标处理并列分数；默认固定 0.5 阈值，不自动搜索阈值。old/current/head/tail 分组必须由协议输入。

## 协议与入口

训练入口从 stdin 读取 JSON。示例 `config.example.json` 默认禁止正式训练。
部署时将入口复制到中性路径，并通过环境或 stdin 提供路径配置，避免在进程参数中暴露项目/方法名。

任务计划 JSON 必须包含 `tasks` 和 `validation_images`；每个任务包含 `train_images`（manifest 中的相对 image 字段）与 `visible_labels`。
本版明确限制每个患者只进入一个训练阶段，验证患者与所有训练阶段隔离；官方 test 不得作为训练或验证。
所有任务完成训练后才开始读取验证图像。可选 `metric_groups` 指定指标分组；不得从测试表现决定分组或选择阈值。
没有自动生成类别序列、筛选有利样本或按未来频次加权。数据的 READY 回执、显式正式授权、任务计划和步数/墙钟预算都必须具备，入口才会运行。

CPU 检查：`python tools/check_multilabel.py`。已有环境依赖为 PyTorch、NumPy、Pillow；真实骨干另外使用原项目的 torchvision、timm 等既有依赖，不新增 scikit-learn 依赖。

## 验证和限制

检查结果见 CPU_CHECK.json 和 NATIVE_CPU_CHECK.json。覆盖掩码梯度、256 组枚举、统计量直接求解与平移、六条件两阶段合成更新、阶段边界恢复、完整合成图像到报告入口，以及原骨干 CPU 前向/反向。
真实 NIH 图像仅做两张加载检查，没有送入模型、没有进行 NIH 参数更新，也没有使用 GPU。

阶段边界恢复已验证，尚未实现批次中途的精确续跑；训练入口不自动重试或覆盖旧输出目录。
全量 1536 维二阶统计量的内存、提取耗时和 GPU 实际步时尚未做资源准入评估。正式任务序列、验证细分、训练预算、独立种子和比较矩阵尚未锁定。
既有 A6 的 BA 门槛不能直接当作多标签 AP/AUROC 的验收标准。
