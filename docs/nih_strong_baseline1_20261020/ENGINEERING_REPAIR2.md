# PNG打包后的像素处理瓶颈与等价修复

原始68358张PNG打包完成，27536987934字节；3张同种子适配验收PASS，打包进程452.001秒，驻留455.131秒。原图不修改。打包仍不足以保证24小时内完成：首个冻结epoch1731.817秒；第二epoch的一个实测窗口136更新/284.585秒，约2.093秒/更新。该窗口与短输入诊断有重叠，不能作无干扰GPU基准。

32张分散训练图的诊断中，缓存读取约0.00025秒/图，PNG解码约0.028秒/图，变换约0.036秒/图；缓存热状态与共享CPU负载会影响绝对时间。不能继续将主要成本归因于逐文件打开。pread未比mmap更快，未采用替换。

修复保持4个DataLoader worker、Torch线程设置、样本顺序和全部随机操作不变。每个批次按原顺序串行生成原RandomResizedCrop与翻转参数，然后每worker以4个线程执行确定性像素操作；原L灰度图在几何变换后再转RGB，其他模式保留原转换顺序。主模型的有效/micro批次、BF16/确定性、LA损失、优化器、学习率与30epoch不变。

资格检查：32张分散图×2骨干×训练/验证共128组，像素张量及Torch随机状态逐项相同；再检查一次随机数回放及其后续批次，均PASS。小样本32图耗时原约1.82–1.90秒，新约0.37–0.40秒，不能直接当正式训练提速。检查累计640次像素变换、128次纯头信息回放、0模型编码和优化更新，32.520秒。另两次输入诊断7.223与21.789秒全部保留；这61.533秒与旧worker驻留重叠，单列不重复加进总墙钟。

第二worker受控终止，676次更新、86490次训练曝光、300次验证曝光；进程保存失败回执与部分候选，退出清理较慢但随后自然退出，未执行KILL。通用异常文案仍提deadline/storage，实际为工程吞吐修复；未达到原24h截止。驻留2099.535秒完整计入。保留第1epoch完整532更新，从其原模型/优化器/RNG恢复；第2epoch未完成144次更新、18432曝光作为重复成本保留，不计入30epoch有效覆盖。合并首次失败后，额外浪费204更新/26112训练曝光。

恢复先用原DataLoader种子和相同worker分配仅回放第1epoch的裁剪/翻转随机抽样，不解码/缩放或做模型编码；恢复后的loader generator必须与完整检查点相同。恢复主CPU/CUDA/NumPy/Python RNG，并复现检查点后已封存验证迭代器的base-seed抽样。第1epoch指标和best权重沿用原封存结果，不重新选择。

正式续跑前，在隔离的可丢弃ImageNet模型上分别测冻结和全量微调：同样的数据流水线、有效128/micro32、模型模式、损失、优化器、精度和确定性；各排除5个预热更新，再测至少60秒端到端吞吐。所有工程更新和曝光单列，这些模型/分数不用于科学结果。守卫共用原时钟/存储限额，测试失败不进入训练。实测后重新从完整检查点恢复，不改变初始化或协议。CLIP速度尚无实测时须注明未知，不能冒称全四臂均能按期完成。
