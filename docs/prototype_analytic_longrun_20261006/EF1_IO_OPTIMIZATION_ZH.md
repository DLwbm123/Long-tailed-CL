# EF1 数据加载开销优化

用户于 2026-10-06 要求优化 GPU 利用率并尽快验证。十次一秒间隔采样中，GPU0 平均77.1%、GPU2平均88.2%，说明该训练窗口并非持续低利用率；不能外推整条轨迹平均值。

仅将固定 canonical 特征提取的 DataLoader 设置为 persistent_workers，避免同一任务内三次提取反复重建 worker。训练数据仍逐 epoch 重建 worker，以保留 epoch 对随机增广的控制。训练样本、batch、优化器、任务划分、原型、反馈与精度全部不变。新任务替换 loader 时释放旧 worker，不跨任务保留旧类图像。

CPU 实测：同一64张图、batch64、4workers、三次遍历。原设置6.119/5.072/4.683秒；复用设置4.238/0.739/0.754秒。六次输出张量和标签完全一致；独立检查亦确认0/2worker间增广一致及canonical三次复用一致。测试顺序固定、文件系统缓存与共享负载可影响耗时，这不是全程倍数加速证据。未进行额外GPU训练更新。

该优化仅应用随后启动的C/D，当前A/B进程使用原快照继续运行；运行INPUT中的source_commit和runtime_optimization记录真实版本，队列原始冻结记录保留。优化后的CPU加载时间不能用作方法的公平速度比较。

最快的科学验证还可复用PA2的A与R1的B：均已完整588更新，数据、种子、任务、epoch、batch与默认保持参数匹配。它们是历史开发对照，不是新增独立确认。若停止当前重复A/B，必须经用户选择后记录协议修订、已消耗时间和保留现场；此文不代表已经停止。
