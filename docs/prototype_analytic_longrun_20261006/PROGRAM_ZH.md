用户于 2026-10-06 明确要求长期实验、每小时监测，并在效果不佳时分析原因、改进和继续实验。本计划落实该授权。此前 PA1/PA2 已完成且结果保持不变，旧 NB-RL/DFD 任务不续跑。

只使用既有 ISIC、Hyper-Kvasir 单标签 train/validation 清单；不增加多标签、RL、数据集、训练样本或测试集访问。不使用旧类图像/逐样本特征回放。允许在下述预算内实现有明确假设的原型、统计量传输、适配器保持项和解析头更新改进；每轮必须先保存协议和代码，再训练，不根据结果回写协议。

本周期自 PROGRAM_STATE.json 记录的启动时间开始，截止 24 小时后；累计 GPU 驻留上限 16 小时，最多 16 条新正式轨迹（含失败和重启），最多 40 次工程验收更新。最多同时占用 2 张已有服务器 GPU，不租新算力、不修改其他进程。每次启动预留队列超时额度，已消耗＋运行中预留＋新预留不得超过总额度；完成后按实际队列驻留释放未使用额度。工程验收也计入总账。

上述是本轮自动推进的明确边界，非承诺必须用完资源。达截止时间或预算上限后停止新训练、整理全部结果并暂停监测；需要用户新授权才扩大周期。每个队列都有服务器端超时，独立于聊天是否在线，且不得越过周期截止时间。

## 已观察到的问题及待检验原因

PA2 完整候选最终 BA=56.0695%，低于 stage_global 的 56.9508%。最后任务旧类召回 52.63% 对 53.08%，新类召回 66.39% 对 68.57%，两者均下降。图数值残差约 8e-16、当前锚点可靠性约 0.989，并不证明旧类漂移外推准确。

原因尚不能确定。候选同时改变了头更新频率与传输机制，缺少与其匹配的冻结特征参照。首轮分别隔离这三处因素，禁止把数值求解正确或高启发式可靠性当作性能证据。

## R1：诊断（立即执行）

复用 PA2 已锁定的 stage_global 和 full_graph 结果，不重复训练它们；来源提交 1bcc3f33c7fa9dda942e1501e806b11e229755d5。新增：

- `graph_stage`：同样多原型、可靠性图和统计更新，分类头改为任务内固定、任务末重算。与 full_graph 比较头更新频率，与 stage_global 比较图传输组合。
- `no_shift`：保持 task-level 头与适配器训练，但旧类统计量不进行位移校正。与 stage_global 比较传输是否有益。
- `frozen_after_first`：第一任务按 stage_global 训练，此后不更新编码器，仅累积真实当前类统计量和解析分类头。与 stage_global 比较持续特征适应是否带来净收益。

配置与 PA2 相同：ISIC 全 8 类、原始全量 train=18718 / val=295、order=[4,0,3,7,5,6,2,1]、seed74002、4 个任务、每任务 2 epochs、batch64、workers4、lambda=.001、FD=10、AdamW lr=.0003 / wd=.01、cosine 至 1e-5、clip5。不更改 train/val 或长尾分布。

预期 graph_stage/no_shift 各 588 次更新；frozen_after_first 仅第一任务 344 次，共 1520 次。冻结组后续任务仍评估全部已见类别。工程验收为同配置小样本两任务，预期 4+4+2=10 次更新，不进入效果结果。检验冻结组跨阶段适配器参数逐元素不变；graph_stage 与 PA2 stage_global 的第一任务验收状态一致。

GPU0 队列 no_shift 后 frozen_after_first，上限 3 小时；GPU2 队列 graph_stage，上限 2 小时。若 GPU2 不可用，按可用显存选择另一张并记录，不影响科学条件。每轮汇总时记录实际 GPU 和共享负载，不能把不同负载下耗时当算法速度比较。

## R2–R3：依据证据改进（由每小时监测推进）

只有 R1 各组终态、结果和成本收齐后才能选择改进。每轮至多 2 个新候选，每个候选改变一个可解释的机制，优先复用现有代码，不做无边界网格。允许的方向：

- 若冻结参照明显优于持续适应：检验更强的特征保持、旧分类头输出蒸馏或固定特征空间的解析更新。冻结参照属于必须报告的强对照，不能为突出候选移除它。
- 若 no_shift 优于全局或图校正：检验保守位移缩放或根据当前任务跨类预测误差校准传输强度；不得只用“锚点信噪比高”声称旧类可靠。
- 若 graph_stage 优于 full_graph：保持 task-level 头，以避免把头更新频率与新机制混在一起；再检验一个保持项或图正则机制。
- 若以上仍不能解释：先用已有逐类、旧/新类、漂移和损失诊断提出一个可证伪假设，再实现至多两个候选；不能仅增加复杂度或反复调同一批验证标签直到变好。

候选数和上述轮次不可自动扩大。允许工程修复，失败目录与回执保留，最多一次同配置全量重启，并计入 16 条轨迹和 GPU 总预算；现有 checkpoint 不含完整优化器态，禁止声称可精确中断续训。健康进程不重启。任何新代码先通过最小数学/机制检查和真实短验收，累计验收上限 40 步。

默认保持 R1 数据、批大小、两轮训练、种子及学习率，优先改变方法本身。若新机制需要不同训练长度，必须在新轮协议中明确且给出匹配控制；本周期单任务最多 3 epochs。

## 冻结候选与新种子复核

筛选主指标为最终 balanced accuracy，必须同步报告尾类召回和遗忘。只有某候选相对任务级基线至少 +1pp、相对最强冻结/不漂移参照有正收益，且尾类下降不超过 0.5pp、遗忘增加不超过 1pp，才进入复核。

有候选时，冻结其全部参数，与当前最强匹配控制一起，使用新训练种子 74003、74004，在 ISIC 和 HK 原始全部类别上复核（最多 2方法×2种子×2数据集=8 条）。HK 使用 PA1 原始 order 和任务划分。若预算不够，先完成 ISIC 两种子，再决定剩余额度是否足够启动一个完整 HK 匹配对。

这是复用验证集上的新训练种子稳健性检查，不是独立测试集确认。不能把未完成的配对当作胜出；不能只发布好种子。到 R3 仍没有收益则结束本周期，发布负结果，不自动继续 R4 开发。
