# RFMiD 均衡、引入支持与旧标签持续阳性的划分设计

状态：训练标签 CPU 设计审查，非正式实验协议、非启动授权。未读取影像、checkpoint、validation/test，0 GPU、0 正式更新；原实验代码、协议、结果与暂停监测不变。私有图片归属仅保存于独立 NAS 分析目录，匿名报告不含样本 ID。

结论：1920 张 train 图每张一次，五任务各 384 张；29 新标签在引入时均有至少 3 正、5 负（实际最少负例 63），每个旧标签在每个后续任务均有实际正负例。2470 次阳性（含 Normal 401 次）及 650 次共阳性标签对全部保留；后续旧阳性 676 次、分布于 560 张图片。不回放、复制或重新采样来制造支持。

## 原顺序的不可兼得与本次调整

原任务顺序最后一组集中五个高频标签，1123 张图片的全部阳性仅在原 T5 组内。若保留全部阳性、未来标签未知、每图只用一次，这些图就必须在 T5 才使用。因此原顺序不能同时满足完整保留与均衡任务，本方案明确重排标签组，不将旧结果重新解释为新方案。

两次均为只用训练标签的约束设计：初稿统一要求引入 5 正例，能完整保留且均衡，却耗尽 ST 的全部正例。修订保留稀缺标签引入至少半数的支持并强制每个后续任务有旧正例；未使用 val、分类效果、训练 seed 搜索或修改标签映射。两份 CPU 审计保留，均不是实验轮。

## 设计规则

1. 保留 29 标签映射与 9/5/5/5/5 任务标签数，每任务 384 图。
2. 最高频的 Normal/DR/MH/ODC/TSLN 依次作为 T1…T5 锚点，使高频标签分散引入。
3. 标签 c 总训练正例数为 n_c，引入正例下限 m_c=min(5,ceil(n_c/2))，负例至少 5。TV/RP/ST 的 m=3，其余标签 m=5；实际出现更多正例也保留。
4. 图片不能早于它的任何阳性标签引入任务；可以为后续旧类支持而延迟。图片 multi-hot 不拆开，全部累计已见标签使用真值，未来标签 mask 为 unknown。
5. 高频锚点在每个后续任务至少 20 正；其余标签若在任务 s 引入，每个后续任务至少 q=max(1,min(5,floor((n_c−m_c)/(5−s)))) 正。若供给不足则该引入时刻不可行，不能制造样本或放宽支持。最后任务没有后续要求。
6. 在以上硬约束中优先较早引入低支持标签：目标 sum_c task(c)/sqrt(n_c)，另加固定微小标签索引平局项。任务内训练 seed 仍 74002，不改变训练频数组或原 mapping。

CPU 使用既有 SciPy/HiGHS 对 163 种训练标签向量的整数数量分配；模式内部按 split-local ID 排序对应图片，ID 不外传。60 秒取得可行解，相对优化 gap 为 1.8106%。所有整数、硬约束及守恒独立审计通过，但没有证明全局最优，不继续搜索以称最佳划分。
