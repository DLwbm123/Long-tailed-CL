# RFMiD 任务分配只读审计

结论：“最后一个阳性标签所在任务”配合累积已见标签真值，能保留全部阳性及共病正标签，并让后续任务出现旧标签正例；但当前固定顺序下 TV 在引入任务没有正例，不能直接沿现有基线协议训练。样本更集中于末任务，完整保留最终监督不等于每阶段都能学好。

本次只读取训练 labels29 与原私有任务计划，未读取图像、模型、val/test，未启动 GPU、未训练、未修改冻结源码或协议。CPU 标签审计约 0.118311 秒；没有产生新的科学轨迹、采样 manifest 或 GPU 费用。

## 与 APPLE 的区别

[APPLE，WACV 2024，§4.1 与 Figure 3](https://openaccess.thecvf.com/content/WACV2024/papers/Song_Overcoming_Catastrophic_Forgetting_for_Multi-Label_Class-Incremental_Learning_WACV_2024_paper.pdf) 在 COCO/VOC 上随机排序训练图（seed 1998），按每任务新类占总类比例分配图片，随后限定当前任务标签。旧类可能出现在新图中但缺失真值，方法用旧模型伪标签及样本回放处理。论文没有给出 RFMiD 实验划分。

因此“随机图片分流”“提供哪些标签真值”“怎样补旧监督”必须分开。最后方案直接使用累计已见标签真值，旧阳性是实标；APPLE 设定中旧标签未标注，不应误作真实负例。它们的监督权限不同，不能直接将效果差异归于方法。

以下仅把论文分流描述迁移到 RFMiD 的一个固定审计例子：同 29 标签顺序，split 内 ID 数值排序后 Python Random(1998) 洗牌，按累计新类比例向下取整。作者随机实现与取整细节未核实，因此不是作者精确划分或 RFMiD benchmark；未扫描 seed。

|只读方案|T1…T5 图片数|可监督真值阳性|未来阳性未监督|旧阳性被当前标签 mask 隐去|引入时无正例|
|---|---|---:|---:|---:|---|
|原最早＋累计真值|95/114/199/389/1123|2146|324|0|无|
|最后＋累计真值|42/83/145/300/1350|2470|0|0|TV|
|APPLE式随机例子＋仅当前新标签真值|595/331/331/331/332|447|1761|262|TV|
|相同随机图片＋累计真值（分离mask影响）|595/331/331/331/332|709|1761|0|TV|

APPLE式例子的 447/2470 只是真值覆盖，不是方法准确率；没有模拟伪标签或回放。随机累计真值控制 709/2470 同样只是标签覆盖。随机例子后续图片仍真实含 262 次旧阳性，只是 current-only 标注权限不给真值；不能称旧标签实际全负。TV 在该固定随机例子的 T1 也为 0 正、595 负，因此并不满足现有基线的引入支持要求。

## 判断与边界

最后分配消除了最早分配的两项结构问题（未来共病阳性永久遗漏、后续旧阳性恒零），但引入支持和阶段样本不平衡仍不合格；当前方案暂不具备直接运行条件。APPLE 为标签缺失型 MLCIL 参考，最后＋累计真值则是旧类可重新获得真值的 MLCIL 设定，两者需分别命名和审计。若后续修改顺序、任务或标注规则，必须独立确定目标与协议后再审计，不能仅换 seed 找到能过的划分。

本审计不能预测 mAP 改善或证明先前效果差的因果来源。没有做患者／眼别或像素重复核对。原实验和暂停监测均未改变。完整聚合数据见 PARTITION_AUDIT.json。
