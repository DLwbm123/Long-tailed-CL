# 正式守卫轮：证据、失败和后续边界

本轮没有形成可评价的完整四轨迹。两条ISIC在task3 epoch2、320更新时的epoch_init守卫均未取得数值证书，HK因依赖停止未启动。全训练屏障未通过，development val没有读取，不能报告本轮旧类收益、新类损害、AIR差距、救回/破坏或交互；各项保持null。test/reserved持续封存。

真实训练与合成可解性的差距已经显现。两背景各7次成功证书中，task2 epoch2和boundary共4次确有活跃约束：正dual为926/955与841/951，保留二次目标收益25.8911%/28.3933%与26.8670%/28.5970%，求解161–270秒。相比合成生产shadow约99.98%的收益保留，真实支持与漂移使约束代价明显不同；这不是受控因果比较，也不是验证分类收益。合成满rank检查证明了特定fixture算术与接线，不保证医学全阶段都在固定求解门内可完成。

另10次NATIVE_FEASIBLE的positive_duals为0，available_gain接近数值舍入，retained_gain为null。虽然原始identity标志为false、判别头有微小变化，不能当成实质作用。保存的成功证书KKT均通过原门；失败task3 epoch2没有保存候选与残差，不能称identity锁死、约束不可能、OOM或确定超时。同状态OFF由构造提供可行参考，当前失败是固定算法未取得所要求的证书。

生产错误分支在获得UNRESOLVED audit后立即抛出ValueError，未先写入该次audit。私有日志只足以确认调用位置和错误类型；840秒软限存在，但该次termination、失败KKT、iterations/trace、solver_seconds未持久化。时间间隔不是明确终止原因。24小时父deadline未触发。此缺口与两次失败全部公开，不在本轮重算以补数、不放宽精度门、不扩大cap、不重启。

成功事件中仅可汇总部分资源：14个去重事件的solver共839.3496134849265秒、guard operation共877.8845012616366秒、native inverse 1594次、成功调用逻辑host输入3778418768字节。它们包含于6278.618359938264秒GPU驻留中，且不含未落盘失败调用的独立计数，不能当完整solver/PCIe总账或额外相加。4个已存私有stage checkpoint共3509000504字节；未加载或导出。实际峰值显存、完整图像曝光计数和最终guard_budget缺失，均保留null。

证书只保护固定frame的current-fit，在optimizer更新后失效；未测same-state OFF/proposal的分类和浮点评分差异，不把这些与独立Core/LT/PMT轨迹贡献混合。历史PMT仍呈ISIC旧类受益伴随新类损害、HK收益微弱，旧开发门没有因此变成通过。

本轮交付至此结束。可提出的新工程修复是：在抛错前先原子持久化纯标量失败audit及资源计数，使未来失败原因可区分；若另获授权，应以新源码/新目录前瞻冻结和CPU校验，不修改本轮，也不靠调cap、阈值、强度或val选择解决。当前未实施新科学修复、未安排重跑或新轮。
