# CPU 判定与后续贡献协议边界

本轮只比较旧 capped 未解问题的新全 dual 解、快照 epoch 与 boundary 原生目标上的可行判别更新。枚举 oracle 验算小问题；最大规模所有 fit 点约束同时在场。证书有效且判别变化>1e-10、目标收益>1e-12、保留可用收益>1% 才称合成有用更新；三项不构成分类有效证据。报告所有正负/identity/未解以及 CPU 资源，不只范数。

九个 CPU case 与所有固定阈值已在 DESIGN_LOCK 冻结，不能因 ISIC 困难改 cap、筛支持、放宽 margin 或按 val 选事件/类/点。未通过即报告限制，不自动正式启动。

未来医学主四格必须另行前瞻冻结：保留 Core/LT，新增守卫运输单独/组合，唯一必要无约束运输对照；同状态 OFF 和独立训练控制分别报告。事件保护不等于整个训练保护。当前未授权 GPU，尚无生产 CPU/真实预检，因此不声明可开跑。
