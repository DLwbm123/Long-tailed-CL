# ISIC封存头支持—查询取舍审计

用户授权本轮：冻结协议后，复用ISIC的C_H、C_F、R_F三个头，只在完整旧S和新S评分；查询结果复用，不重新拟合、不调参、不打开E，完成后公开全部逐类正负变化和成本。源码和协议在读取支持并评分前公开冻结。

## 唯一问题与预先判定

固定主比较C_H→C_F：完整支持域上是否同时满足class3净正确数增加、class4净正确数减少？严格用delta_correct(class3)>0且delta_correct(class4)<0判定，零变化单独报告；这是符号假设检验，不是统计显著性检验或部署门槛。两个查询上既有方向只作已知参照。

若支持端同向，说明本固定配方下支持域已有取舍，但不证明其不可避免；若class3改善、class4不退化而查询class4退化，则否定这个具体类别级同向假设，将解释重点移向支持到查询的迁移。支持端表现好不等于泛化充分；支持端仍有错误也不能证明表示或所有线性头不可能。

固定次比较R_F→C_F，检查class3/class4共同改善是否也出现在支持端。全部6类、两条比较、支持及两片查询的正/负/零变化均保留；class0/2作为另两个有较多查询样本的检查，class1/5不删除。主要机制依据class3/class4配对结果，不以极小类引起的总体宏BA翻转替代。逐类总体BA贡献始终为delta_recall/6，不删类、不重设分母、不更改既定评价结果。

## 冻结输入与评分

seed74002、首转移4+2、原类序、1536维float64、原零适配器归一化、logits=8zW，无bias/列归一化/温度变化。C_H来自linear_ce_head1，C_F来自full_support_linear_ce1，R_F来自offline_information_ab1的B；来源与公开交付提交精确绑定见锁文件。头与原缓存只读。

完整旧S逐类375/23/208/2630条，新S2254/36条，共5526条。共享归一化一次、三头评分16578个样本—头组合。报告逐类正确数、召回、CE、误分类到旧/新组、全部混淆单元格；每条比较保留逐类/分组救回、伤害、错转错。支持端margin/rank分布只辅助描述，不能由平均margin推断BA。

完整S是共同评分域，并非共同训练集：C_H只拟合H＋新S，C_F和R_F拟合完整旧S＋新S；三个头都拟合过同一新S。支持和查询不是逐样本配对，配对仅在同一数据域内进行。不同域的正确数不直接相减，报告各自计数及召回变化。
