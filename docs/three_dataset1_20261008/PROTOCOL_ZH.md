## 数据与顺序

依据用户提供的 Lai 等 GPA 论文第 5–6 页：CIFAR 为 CIFAR-100-LT，IF=100，初始 50 类，后续 5×10 类。ordered 按训练样本数从多到少，shuffled 使用同一批长尾样本的固定类别排列，不能因顺序重新采样。CIFAR 计数采用参考 LT-CIL 加载器的向下取整与 RandomState(0)，shuffled 使用仓库 docs/official_cifar100_lt_order.txt 的参考排列；论文作者仓库 README 尚无实现说明，未声称已核对未公开的补充代码。

ISIC 保留 8 类自然长尾及原身份隔离划分，采用 4＋2＋2；Hyper-Kvasir 保留现有 23 类 official-name-sorted 命名空间、自然长尾及划分，采用 13＋2×5。医学 shuffled 为 RandomState(74002) 的一次固定类别排列。实际训练计数、两种排列及身份重叠检查保存于 DATA_PROTOCOL.json。这是医学数据适配，不是论文原始医学基准。

各设置共享外层训练和评估划分；训练内 fit/meta 按身份组固定 seed74002 作约 80/20 划分，两种顺序保持成员一致。meta 用于权重控制且参与任务末最终头重拟合，不作为独立验证。医学评估沿用开发集，医学 test 保持封存；新 CIFAR 基准用官方平衡 test，仅在各轨迹训练全部结束后评估冻结的各阶段模型，不据此选模型、参数或追加训练。

## 评估与执行

共 3 数据集×2 顺序×4 方法＝24 条独立轨迹，seed74002。报告平均增量 top-1 Acc、最终 Acc、固定任务准确率矩阵及旧任务从历史峰值到最终的平均遗忘；另报 BA、逐类召回和训练频率 many>100、medium20–100、few<20 的 micro/macro 表现，空组记 null。

先进行最多 900 GPU 秒、零适配器更新的 CIFAR 原生预检，允许最多 8 步策略更新以验证完整控制链；预检结果不作为方法筛选，也不复用预检模型。通过后，24 条正式轨迹各最多 6600 秒，计费所有进程实际驻留；队列受独立总预算和截止约束。一次技术失败保存现场。用户已于 2026-10-09 授权每小时监测并修复故障后继续；须先诊断再恢复，仅重跑未完成单元，保留失败尝试、原始源码、已完成结果和累计消耗，不重置截止或预算，不改变科学协议。
