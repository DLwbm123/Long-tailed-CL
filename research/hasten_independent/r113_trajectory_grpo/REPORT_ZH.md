## 研究问题与实现方法

研究问题是：在长尾持续学习中，策略能否学到当前评分未充分反映、却对后续学习有用的记忆保留价值？本轮检验这一机制假设，不预设GRPO一定有用，也不把使用GRPO本身视为创新性证据。

| 组成 | 当前实现 |
|---|---|
| 数据流 | 同一6821个TRAIN图像组件、23类，分5+5+5+4+4阶段；每流种子74003/74004 |
| Ordered | 按类别出生样本数从多到少到达 |
| order0 | 预先固定的分层打乱类别顺序，头尾类混合到达；0是顺序编号 |
| 分类器 | 冻结视觉编码器；rank16聚合器、余弦分类头；AdamW lr.001/wd.001、KD温度2、batch64 |
| 实际流训练 | 每阶段200步行动前训练、100步行动后训练；每臂保留自己的分类器、优化器与记忆 |
| 记忆证据 | 每臂总计≤256个特征token、528568字节，包含S/FIT/AUDIT；不是256个文本token |
| 角色分离 | S用于模型更新、状态描述和候选生成；FIT只提供策略训练反馈；AUDIT只做外层评分 |
| 查询成本 | 每类FIT/AUDIT各1个固定global token，查询占2C；23类时S容量为210，不是256 |
| 记忆动作 | ZERO/BAL合法锚点及risk1/2/4、cover4、random2局部编辑，去重后最多12个候选；保持核心、覆盖、父组件耦合与锚点配额 |
| 策略 | 小型类别等变ResidualPolicy，类特征14维、动作特征10维、隐藏宽度64；输入仅为行动前合法S信息 |
| 决策 | 策略先选动作，随后执行；实际流不再逐候选执行后按FIT取最大值。每个后继状态继承本条轨迹的模型和记忆 |

分类器、actor和优化器参数另作为模型状态计入RAM/GPU/磁盘资源账，不包含在528568字节的历史特征证据账中。

每个真实阶段的策略训练，只用已经到达的合法前缀构造H3伪到达任务。每组从同一起点执行4条策略轨迹，另执行1条ZERO参考轨迹；后两步也重新生成候选并由策略决策，续接不再固定ZERO。每条轨迹实际执行100+200+100+200+100=700次分类器更新。训练中的伪到达不是尚未到达的真实未来类别；实际五阶段连续流另行评价。

LONG_GRPO以整条轨迹的FIT回报作为各步优势信号：

`R = mean_h(Δmacro_BA) − 2 × max_h[max(0, −Δoldtail_BA − 0.005)]`

变化相对同组实际执行的ZERO轨迹。旧尾类定义为出生样本数<250、且早于当前真实阶段到达的类别。MYOPIC_GRPO使用对应单步收益，不累计后续回报。组相对优势由4条on-policy轨迹减组均值、除总体标准差+1e−6；ZERO是绝对参照，不是强制加入的off-policy GRPO样本。全负回报组也可能有正相对优势，因此仍须看相对ZERO的绝对效果。

优化设置冻结为每组2epoch、actor AdamW lr1e−4/wd.001、概率比clip.2、对冻结均匀参考的精确分类KL权重.01、梯度裁剪1。没有学习型奖励模型或验证器，没有根据中间结果调整学习率、奖励、种子或保护阈值。

## 同轮对照及公平口径

| 方法 | 用途与反馈 |
|---|---|
| ZERO | 固定均匀下一动作参照；也对应均匀初始策略在argmax同分时的ZERO行为 |
| BAL | 固定均衡记忆规则，标准实现加必要的证据保护 |
| MYOPIC_GRPO | 即时回报RL，检验收益是否需要多步后果 |
| LONG_GRPO | 主方法，使用完整H3回报训练 |
| SUP_SHARED | 同批反馈的完整轨迹模仿：使用LONG采集的同一组状态/动作描述及FIT回报，模仿最好正回报轨迹；没有正回报则模仿ZERO |

SUP_SHARED训练的是候选策略，不是重做分类器SFT；它不额外执行分类器候选。共享反馈生成成本计在LONG来源，不宣称其为零成本。其训练数据由LONG行为策略采集，因此属于共享轨迹上的监督对照，不是独立执行全部候选得到的监督oracle。MYOPIC与LONG分别从各自合法前缀on-policy采样，反馈类型与组数匹配，但数据不是逐轨迹相同。五臂的真实流模型和记忆相互独立，只有当前到达编码可以共享。

## 从R112到R113：证据分别说明什么

R112是共享ZERO donor起点的候选分支比较，没有训练RL：LOCAL相对ZERO的macro BA提高Ordered0.4573、order0 0.6832个百分点，但原R分别为−0.020256、−0.070970，冻结判定C。它没有证明RL无效，也没有证明全流程方法有效。

R112保存候选的事后AUDIT安全oracle显示，全部候选相对仅锚点的额外R为0.016135/0.016700；加FIT门后保留约93%–94%的全部安全上限。这说明保存表中有更好的候选，不能证明FIT排序可靠、选择器可学或RL必要。oracle使用AUDIT答案，不能作为实际方法成绩。每条流反复使用的只有23个不同图像组件，部分收益集中。

R113因此把问题改为真实训练多步策略，并在各自连续真实流上比较；它与R112的动作执行、状态分布和评估范围不同，不能把两轮绝对BA相减声称提升。已分析过的R112 AUDIT继续是开发材料，不是新的独立确认集。
