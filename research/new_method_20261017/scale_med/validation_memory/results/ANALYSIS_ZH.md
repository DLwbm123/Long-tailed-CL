# 结论：本轮不支持继续开发二阶验证记忆

协议源码先以4820799封存。首次运行因访问保护的Path/字符串比较错误，在旧类退休探针处失败，未进入新增阶段与测试；9.21秒失败成本保留。工程修正51b3cbb在独立目录重跑，退出0，成功轮30.87秒，累计40.07秒。未改变划分、候选、阈值或科学停止规则。

## 一、历史验证的必要性没有超过简单控制

ISIC完整验证选择alpha=.0001，验证BA69.3817%，优于首阶段固定.01的67.1344%。因此相对FIRST，确实存在2.2474pp的验证选择遗憾；不能说所有选择器已经一样好。

但CURRENT与BIRTH也都选择.0001，已经达到完整验证集在这三个候选中的最优值。预设第一门比较的是最强简单控制而不是只比较FIRST，故结果为STOP_NO_SELECTION_HEADROOM。严格表述是：本次转换与三个候选下，新增历史验证状态没有展现简单控制之外的选择能力。这不是关于更多候选、更多转换或所有历史验证方法的否定。

这里的“最强简单控制”借助完整验证集在FIRST/CURRENT/BIRTH中确定，是测试前固定的特权诊断参照，不是免费可部署的元选择器，也没有依据测试成绩选择控制。

HK的FIRST、BIRTH、MOMENT与完整验证都选择.0001；CURRENT选择1，覆盖验证BA损失8.8475pp。说明只看新类确实可能选错，但FIRST和极小的标量出生档案已经能避免这次错误，不能据此证明额外二阶验证矩必要。HK缺一个旧类的独立验证，以上仅指覆盖的14类。

## 二、精确保留MSE没有精确保留BA排序

ISIC中，完整验证BA偏好.0001，而完整验证MSE与MOMENT都偏好.01。摘要与逐行直接计算的MSE最大误差仅1.22e-15，HK为3.33e-16。因此这里没有压缩误差，也没有损失计算近似：这是两个指标的真实排序差异。

候选.0001相对.01在ISIC旧类验证BA低1.6063pp，新类高9.9548pp；4旧+2新的类别平均给出总验证BA高2.2474pp。二阶平方损失还受输出幅值与错误置信度影响，并不只统计argmax正确性。这个机制解释有候选分解支持，但没有进一步定位到个别特征或样本的因果证明。

## 三、完整验证BA也不是测试性能上界

ISIC测试中，FIRST/MOMENT为55.7364%，完整验证BA/CURRENT/BIRTH为51.6512%。差值为+4.0853pp，配对95%区间[-.0195,+8.2596]，不能排除零差异。验证BA最优头在这个测试上反而较弱，说明完整验证BA只能作为同一验证样本上的选择参照，不能当作泛化oracle。

因此，不能把MSE的验证BA遗憾直接写成“方法的测试失败”，也不能利用这次测试结果事后改称MSE是更好的普遍选择标准。MOMENT与FIRST在两个数据集均选择同一alpha，预测也相同，本轮没有相对FIRST的新增效果。

HK测试FIRST/MOMENT/BIRTH/FULL_BA/FULL_MSE均为68.1195%，CURRENT为57.6632%。新类验证仅由很少留出组支持，且一个旧类验证缺失；这个差异不能解决其全类验证覆盖问题。两数据集测试均历史暴露，患者隔离仍未知。

## 四、成本也没有自动成为优势

实际实现为float64稠密矩阵：额外验证状态ISIC18.094MiB，HK18.199MiB；同批逐行验证特征float64等价分别13.230和7.523MiB。当前实现的验证状态反而更大。

对称上三角的理论状态分别9.088和9.193MiB：ISIC理论上可小于逐行特征，但HK仍更大；本轮未实现上三角存储，不能将理论数字当实测节省。逐行特征只是特权成本参照，不符合部署时旧逐样本特征退出的约束。聚合矩也不提供自动隐私保证。

学习阶段墙钟6.50秒，审计0.36秒，评测6.59秒；其余为进程启动等开销。学习峰值RSS约950.2MiB、GPU分配峰值约44.7MiB。摘要构建和选择未分开计时，包含在学习阶段，不能声称独立选择加速。已有缓存提取、编码器和原始数据准备成本排除。

## 停止决定

停止本轮二阶验证记忆的压缩与扩展。原因共同来自：相对简单控制没有恢复额外验证选择能力、MSE与BA排序不一致、矩摘要没有改变FIRST选择、实际状态没有节省。工程检查通过仅证明计算与访问边界正确。

若未来重新立项，需要新的独立证据证明：简单控制在持续转换中系统性失效，而历史验证能纠正这种失效。当前结果不足以启动压缩、换种子、增加候选或用测试挑选新代理指标。本次没有追加这些实验。
